# v0.4.21 — DKey conversion: 3 DNF recoveries, up to 7.8×, 0 answer changes

**70 commits since v0.4.19.** (v0.4.20 was a packaging-only release cut from `release/v0.4.20`, never merged to main — this is the first release carrying reasoner changes since v0.4.19.) The user-visible headline is a conversion-time fix for
data-property-heavy ontologies. The rest is correctness fixes, two new opt-in flags, and a
substantial correction pass over the design record.

## Behaviour changes (defaults)

| flag | change | effect |
|---|---|---|
| `RUSTDL_DKEY_STR_SIZE_INDEX` | **new, default ON** | size-indexed `xsd:string` subsumption seeding |
| `RUSTDL_DKEY_GROUP_SKIP` | **new, default ON** | skips the provably-droppable DKey disjointness block |
| `RUSTDL_PREP_DEADLINE` | **flipped ON** | bounds prep only while the budget is still meetable |

`=0` reverts each.

### What the DKey pair delivers

Conversion on data-property-bearing ontologies was dominated by two O(k²) seeding loops.
Measured on `ore_ont_10929` — a DNF with **12 classes** and 110,802 `DataPropertyAssertion` over
**60,323 distinct literals** — conversion was **96 s of a 97.6 s** run: `subsumption_ms` 73,872
(the string bucket's ~3.29 × 10⁹ ordered pairs) and `disjointness_ms` 20,484 (248 M pair-visits,
**100% of them discarded**).

Both are now enumerated only where an edge can exist. **Exact, not approximate:** a `Set ⊆ Set`
edge between distinct keys requires `|a| < |b|` (equal ranges share one `ClassId`), and the
droppable disjointness block is exactly value-only × value-only in a non-collapse component.

## Correctness fixes

* **`realize` dropped derived individual equality** — both halves closed. The functional half
  ships on the default path (the fast-path gate now refuses a functional-ish role together with an
  `ObjectPropertyAssertion`); the inverse-functional half is `RUSTDL_INVERSE_FUNC_MAX`
  (**default OFF** — its flip sweep found 3 ontologies regressing to DNF against 17
  Konclude-confirmed gained entailments, so it is a performance-blocked completeness gain).
* **`--global-timeout-ms` now charges parse time**, which it previously did not (`ore_ont_7192`
  72 s → 55 s, rows identical).
* **`justify`/`repair`/`laconic`** reuse `PreparedOntology` across queries, and the justification
  search input is now in canonical order — output was **not run-to-run reproducible** before
  (#58, #59, #60).
* Two host-speed-dependent canaries fixed at the root (#61, #62), plus the observability gap that
  cost both: `ClassificationStats::prep_unbounded_budget_spent` and `Realization::incomplete`.

## New opt-ins (default OFF)

* `RUSTDL_LABEL_CACHE_PROBE` — differential escalation probe for the per-class label-cache budget.
  Fixes an 8× starvation a floor cannot (`ore_ont_5107` 6.65 → 1.14 s). Held OFF by a **measured
  ship-vs-ship dead heat**: net +0.01 s over 509 ontologies.
* `RUSTDL_INVERSE_FUNC_MAX` — see above.
* `RUSTDL_CB_ELI_PROBE` / `cb_eli_eligible` — Horn-ELHI fragment gate, dead code pending a market.
