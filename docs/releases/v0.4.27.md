# v0.4.27 — the self-verifier stops crying wolf, and one more datatype clash lands

Four fixes. The one that matters most is not an engine fix at all: `verify-el`, the
crate whose headline claim is that a `Violated` verdict is a real engine defect, was
**0-for-8** on the corpus — every violation it reported was its own. It now reports
**zero** false positives across all 1,920 ontologies.

## The engine fix

**Range × enumeration DKey disjointness was never seeded (#42 item 2, PR #100).**
`DataHasValue` and facet restrictions lower into a datatype's **range** bucket;
`DataOneOf` lowers into a separate **enumeration** bucket. Disjointness was seeded
*within* each and never *across*, so `∃p.{5} ⊓ ∀p.{1,2}` did not clash even though
5 ∉ {1,2} — `classify` said satisfiable where HermiT said unsatisfiable. The same shape as
#86 (cross-**datatype** range × range), one level down.

`xsd:string` was unaffected, and that asymmetry is what found it: both string forms lower
to one `StrSet`, so they were already compared. **Not a dropped construct** — `dropped` was
empty on every probe, so the axioms converted and the clash was simply never derivable. A
silent miss, which is why #42 had recorded it as "only `xsd:string` enums are handled".

Same-datatype pairing only, which is what keeps `contains` exact: both operands reach their
DKey through one datatype's parse path, so equal values are bit-identical keys. The
cross-datatype case stays a deliberate sound MISS, pinned by a canary to **flip, not
delete**.

## The instrument fixes (#87)

**F5 — a truncated model cannot support a defect claim.** `fold_build_reasons` kept
`Violated` when a build reason said the model had been **cut**. A truncated model is
smaller than the axioms describe, so an axiom that would have been witnessed cannot be, and
the violations are artifacts. Four 50k–60k-class ontologies reporting 20,292–92,573
"violations" now exit 3 (no verdict) rather than 2 (real defect).

Deliberately narrower than "any reason": a *localized* gap — a `LabelNotClosed` naming one
node — leaves a violation elsewhere meaningful, and downgrading that too would discard a
true positive.

**F4 — `⊤ ⊑ C` never reached model elements.** `required_atoms` on `⊤` returns an **empty**
antecedent, and the builder read empty as "no rule" when it means "fires on every element".
Four ontologies whose violation counts equalled their `owl:Thing`-LHS axiom counts
*exactly* now verify with 0. Fixed at the `FiniteModel::intern` chokepoint — where all
three label-construction sites route — plus universal-rule firing, since a label floor
cannot build the `⊤ ⊑ ∃r.C` case.

**F4 and F2 were one mechanism.** F2 was a separately-documented builder false positive; it
is closed by this fix. Neither write-up had noticed they were the same sentence.

## The packaging fix

**The Protégé plugin registered nothing (#79, PR #101).** `plugin.xml` was not well-formed
XML, so Protégé's "XML contribution" failed and the plugin was never installed.

## What the clean instrument does and does not license

**Licensed:** `verify-el` can now be run **unattended** as a D10 hunter — a fragment gate
certifying complete while the engine drops an axiom. That is the prize, because the loop
behind most of this project's recent engine fixes has been *reactive*, and a clean
instrument makes it systematic.

**Not licensed:** "no engine defects exist."

* **Coverage is 19%** (362 of 1,920 checkable). The binding constraint is the `is_pure_el`
  fragment restriction, not defect density.
* **196 ontologies are UNMEASURED**, not passing — they hit the 60 s cap, which is "no
  verdict reached", a different thing from an exit-3 `Unresolved`.
* **F1 and F3 are still live** builder false-positive mechanisms. A `Violated` is therefore
  a **lead requiring adjudication**; what changed is that it is no longer *guaranteed*
  spurious.

## Three things this release cost, worth keeping

**The obvious fix to F4 was the dangerous one.** `required_atoms` returns an empty vector
both for `⊤` and for every shape it cannot decompose (`Some`/`Or`/`Not`/`Min`/`All`).
Reading empty as "universal" would apply consequents to every element unconditionally, and
the failure direction is not a spurious violation but a **false all-clear** — the one
outcome the crate exists to prevent. The predicate therefore tests for `⊤` structurally.

**A guard written for exactly that did not guard.** Its first version asserted only that a
baseline verifies, and under the sabotage it *passed* — an unrelated test caught the
sabotage instead. Rewritten around a `DisjointClasses` that makes the over-broad labelling
observable; it now fails by name.

**A doc citation went stale and hid a coverage hole.** `fold_build_reasons` cited
`cascade.ofn` as producing `Violated` plus three build reasons; cascade now carries **zero**
— #81 changed it. Checking every fixture, the `Violated`-with-reasons combination is
**unreachable from any of them**, so that arm had no coverage at all. Five new unit tests
are now its only coverage.

## A trap that outlives this release

From F4: **any oracle comparison that counts `Thing` rows reports spurious MISSED on any
ontology asserting `⊤ ⊑ C`.** This project has been bitten once already — 73% of an apparent
~1,795-row gap against Kobayashi-MaRust was the same ⊤-convention artifact. Worth auditing
in the comparison tooling independently.
