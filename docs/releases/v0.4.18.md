## Headline: one output-visible change, read this first

`classify` no longer emits `direct` edges whose **subject is an unsatisfiable class**, in
either the text output or `--json`'s `direct_subsumptions`. On an ontology with
unsatisfiable classes the row count drops — `pizza` goes 314 → 188 rows.

Nothing is lost. An unsatisfiable class denotes `⊥`, so it is subsumed by everything; it is
already reported in the `unsat` list / `unsatisfiable` array, and "⊑ everything" follows
from that. `direct_subsumers` is **unchanged** and still returns the mathematically correct
set; only the taxonomy *view* filters.

This is not a new convention. `build_classify_json` already excluded unsatisfiable classes
from `equivalent_groups`, recording the same argument ("they are all mutually equivalent
(≡ ⊥) … they belong in `unsatisfiable` (the bottom node)"). The equivalence half was
excluded; the direct-edge half was missed. **If you parse `direct` rows and depend on the
old behaviour, this is the release that changes it.**

## Performance

Eight ORE ontologies that could not be classified at a 60 s cap now classify — the entire
`saturate` bucket of the 164-ontology DNF tail, from 0 to 8.

| ontology | v0.4.17 | v0.4.18 |
|---|---|---|
| `ore_ont_5753` | DNF | **0.9 s** |
| `ore_ont_11287` | DNF | **1.3 s** |
| `ore_ont_12567` | DNF | **16.7 s** |
| `ore_ont_14459` | DNF | **45.5 s** |
| `ore_ont_8486` | DNF | **50.1 s** |
| `ore_ont_10689` | DNF | **56.8 s** |
| `ore_ont_868` | DNF | **57.5 s** |
| `ore_ont_9674` | DNF | **57.6 s** |

**Three of those land at 56.8–57.6 s against a 60 s cap. They are recovered MARGINALLY —
a slower host loses them again.** Quoted that way deliberately.

Five changes, in descending order of breadth:

1. **Feature flags out of the wedge hot loop** (`88e0634`) — `hyper_*_enabled()` was read
   per iteration. **−5.56% corpus wall over 1,920 ontologies, 0 regressions**, up to 36× on
   the env-lock-bound member (`ore_ont_15010`). The one change here with a full sweep behind
   it already.
2. **D4 data-cardinality scans de-quadratic'd** (`e7ee18e`) — two passes rescanned the whole
   `(individual, property) → values` map per (constraint, individual) pair,
   `O(|F| × |I| × |I·P|)`. `ore_ont_5753`: 15 × 20,118 × 20,149 ≈ 6.1e9 steps ≈ 33.5 s of
   conversion, 89.85% of a perf profile. Conversion **33.6 s → 0.72 s (46×)**;
   `ore_ont_11287` **29×**.
3. **Taxonomy: no direct edges for unsat subjects** (`906324c`) — see above.
   `ore_ont_12567` **757,999,247 rows → 260,991** (2,904×) and **103.1 s → 16.7 s**, now
   faster than Konclude's 18.08 s on the same file. The removed rows were 99.97% of the
   output: 4,202 unsat classes × 180,328 = 757,738,256 exactly.
4. **The CLI no longer converts every ontology twice** (`039fb25`) — the dropped-axiom tally
   came from `dropped_axioms`, i.e. a second full `convert_ontology`. Invisible while
   reasoning dominates; on a conversion-bound ontology it doubles the wall.
   `ore_ont_868` **92.3 s → 57.5 s**, plus four siblings.
5. **`prepare` reuses the EL closure** (`387f0c5`) — `classify_top_down_internal` computed a
   saturation closure, then `from_internal_with_deadline` ran the identical fixpoint over
   the identical unmutated ontology again. Roughly halves `prepare`.

## API (additive)

* `ClassificationStats::dropped: DroppedAxioms` — the conversion's dropped-axiom tally,
  carried on the result so callers need not re-convert to obtain it.
* `Classification::taxonomy_direct_subsumers(&str) -> Vec<&str>` — `direct_subsumers` with
  unsatisfiable subjects filtered; the view both output writers use.

Both are additions. `ClassificationStats` is constructed with `..Default::default()`
throughout, so the new field does not break existing construction.

  own admission, so the green net is non-regression evidence for change 2 as well. Its real
  evidence is the canaries and the verdict identity on `ore_ont_5753` / `ore_ont_11287`
  (clash `true` / `false`, unchanged, agreeing with Konclude and KM).
* **9 new canaries, every one sabotage-tested.** Two needed correcting before they guarded
  anything: the D4 fixture first measured `seed_disjoint_bucket` instead of the loop under
  test (failing identically before *and* after the fix), and at 1,500 individuals a
  deliberately re-introduced bug **passed**. Sizes are calibrated, not guessed.
* Workspace tests green (`owl-dl-py` excluded — pyo3 cannot link libpython in this
  environment, pre-existing). fmt + clippy clean.

## Not fixed, recorded

* `consistent` and `realize` still call `dropped_block`, so they still convert twice. Cheap
  now on ABox-heavy inputs, but ~2× on genuinely large files (`consistent ore_ont_868`
  remains ~70 s+). Needs a different mechanism, since `is_consistent` returns a bare `bool`.
* The four `unsat_probe` DNFs are untouched and are a different root cause: 1.3–2.6k axioms,
  ~0 s conversion, ~100 s in `unsat_probe`, Konclude 0.10–0.46 s.
* The DNF tail goes 164 → 156. None of these five changes is the "algorithmic" work the peer
  triage pointed at — two were quadratic loops, one an output convention, two duplicated
  work.
