### Part A — five dropped `⊑ ⊥` shapes (no flag; a correctness fix)

The fragment gate admitted shapes the saturator's rule collector discarded, so a missed
entailment was reported as a *complete* closure — the "D10 unsound-completeness" class, and it
reaches the public `sat`/`classify` APIs, not just the banner.

- `And(b₁…bₙ) ⊑ ⊥` → new `ConjunctiveUnsat { bodies }` rule feeding the existing `enqueue_unsat`
- `⊤ ⊑ ⊥` → `ElRules::global_unsat`, marking every user class unsat at seed
- `∃r.A ⊑ ⊥` → the interned existential marker pushed onto `directly_unsat`
- `∃r.⊤ ⊑ ⊥`, `Domain(r,⊥)`, `Range(r,⊥)` → unified `ElRules::poisoned_roles` (a role provably
  edge-less), plus a post-collection pass marking **nested** existential markers on poisoned
  roles (order-independent)
- inconsistency reporting via `Subsumers::top_is_unsat`

**Soundness note worth keeping:** "every user class unsat" is *not* a valid inconsistency
signal — `{A ⊑ ⊥, B ⊑ ⊥}` leaves a non-empty domain of things that are neither, so the KB is
consistent. The signal is `⊤` being unsat. My first instruction here proposed the all-classes
condition (copied from `diagnose.rs`, which uses it only as a *trigger* to consult the
authoritative verdict); a subagent's advisor caught it.

**Part A is corpus-inert on all measured data** — the shapes occur nowhere in
`ontologies/real` or the fixtures. It is a correctness fix with no measured performance or
completeness delta on this corpus. Do not oversell it.

### Part B — RHS-negation canonicalization (`RUSTDL_NEG_TO_BOT_GCI`, default ON, `=0` reverts)

Runs **pre-NNF** over `InternalOntology.axioms` late in `convert_ontology`. Pre-NNF is
load-bearing: post-NNF `¬∃R.C` and `¬(A ⊓ B)` have already become `∀R.¬C` and `¬A ⊔ ¬B`, both
out-of-fragment. Emits **one `⊥`-GCI per negated conjunct** — folding them into one is strictly
weaker (`X ⊑ ¬A ⊓ ¬B` ≠ `X ⊓ A ⊓ B ⊑ ⊥`; that flaw was in my spec and was caught in review).
`told.rs` learned the `And([A,B]) ⊑ ⊥` shape so told-disjoint coverage did not shrink.
Handles `Axiom::SubClassOf` only.

Measured (release): `ore_ont_9318` (39 433 classes) **21.8 s hybrid → 0.93 s pure-EL**, closure
byte-identical (19 470 rows); `ore_ont_2397` **DNF >200 s → 1.03 s**; `ore_ont_10032`
**DNF → 2.41 s**. Gate probe: **13 ontologies flip to pure-EL, 5 recovered from DNF**.
A 60-ontology ORE ON-vs-OFF sweep: 58 byte-identical, 0 diffs, 0 mode changes.

### `441a90a` — two more D10 bugs, found by *reading* the gate

- `is_saturator_axiom` accepted `DisjointClasses` without inspecting members; the engine keeps
  only atomics. `DisjointClasses(A, B⊔C)` + `X ⊑ A ⊓ B` ⟹ `X` unsat, but the fast path
  reported it satisfiable under `# fragment: Horn (… complete)`.
- Both gates accepted non-atomic `Domain`/`Range`; `role_domains`/`role_ranges` are atomic-only.
  `Domain(r, P⊓Q)` + `X ⊑ ∃r.⊤` ⟹ `X ⊑ P`, `X ⊑ Q`, but **zero** subsumptions were reported
  under `# fragment: pure-EL (… complete)`. This one is in `is_pure_el`, so no env flag rescued
  it.

**Fix = tighten the gate to reject what the engine drops, not extend the engine.** FP-safe by
direction: tightening only routes more ontologies to the sound-and-complete hybrid path. Cost
is 2–7 ontologies getting slower and correct.

Bug B's *default-flag* miss persists after the fix for a separate, documented reason — the
same-tier walk gap; `RUSTDL_CLASSIFY_SAME_TIER=1` recovers `X ⊑ P`/`X ⊑ Q`.

## 6. Memory tail: four mechanisms proposed, all four refuted

Full detail in `docs/2026-07-29-memory-tail-localization.md`. Measurement only; **no fix
built, deliberately.**

`ore_ont_9347` (8.6 MB input, **114 classes**): convert+absorb **14.2 GB / 123.5 s**;
+saturation **19.1 GB** (completes); full classify **238 GB → OOM-killed**.

Refuted: D4's dense `num_total_classes²` matrices (saturation adds 4.9 GB; 114 classes; the
rewrite would address ~2% of peak); parallel fan-out (32× threads → 3.4× memory); unbounded
main-tableau graph (`RUSTDL_ANYWHERE_BLOCKING=1` changes peak RSS by **0 bytes**); the label
cache (inert). Wedge accounts for ~18%. Growth is steady ~40 MB/s, not explosive.

**Still unknown** where the remaining ~30 GB lives. Candidates: the once-per-classify
`PreparedOntology::from_internal` snapshot, or per-pair retention.

**One over-read, walked back in the doc:** `--pair-timeout-ms 50` showing no RSS change is *not*
a null result — 114 classes is ~13k pairs; at 50 ms each that is ~650 s of work against a 130 s
window, so the cap never bounds total pair work.

**The lesson:** two of the four refuted hypotheses came from this repo's root-cause notes, each
**correctly measured on a different ontology** (`ore_ont_3914`, `alehif`) and then generalised
by wording that does not carry its scope. **The memory tail is not one phenomenon.**
