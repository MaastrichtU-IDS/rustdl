# v0.4.26 — three wrong answers on the default path, all root-caused rather than flagged around

`classify` answers change on this release, in the direction of finding entailments it
previously dropped. Every fix is a **silent** defect: a wrong answer with
`incomplete: false`, which a consumer had no way to distinguish from a complete one.

Two of the three are the same shape one construct apart. The third is one line in the
wedge's matcher, and it had been misdiagnosed twice before.

## The fixes

**`classify` missed an unsatisfiable class when the cardinality qualifier was COMPLEX
(#91, PR #98).** `A ⊑ ≤1 r.(B ⊓ C)` with `A ⊑ ≥2 r.(B ⊓ C)` makes `A` unsatisfiable —
Konclude, HermiT and rustdl's own `sat A` all say so, and `classify` reported
`unsatisfiable: []`. classify's unsat probe trusts the wedge's `Sat` unless
`needs_verify` fires, and that expression already excluded two constructs the wedge
cannot count (`data_counting_classes`, and `nominal_counting_classes` from #49 — whose
own comment reads *"Same defect one construct over"*). This is one further again:
`cardinality_qualifier` Tseitin-names a complex filler, so the wedge counts a synthetic
name without relating it to the members and cannot see the `≤` and `≥` range over the
**same set**. `RUSTDL_COMPLEX_QUALIFIER_VERIFY`, default ON.

**`classify` silently dropped `ObjectHasSelf` constraints, in or out of a `∀` (#90).**
`eval_order` built a *tree* over each clause's role atoms and refused any body whose atom
targeted an already-bound variable — and a refused body got **no match plan at all**, so
the clause never fired and its constraint went unenforced. Such an atom is not
unsupported: with both endpoints bound there is nothing to enumerate, so it is a
**filter**. Now `ClauseMatchPlan::filters`, checked at the leaf.

**`¬∃R.Self` at head position was deferred out of the wedge theory.** `emit_head`'s `Not`
arm handled only an atomic inner, so the axiom left the clause set entirely — a silent
drop, not a refusal.

## What made these hard to find, and what that cost

**"No flag recovers it" was a clue, not a dead end.** #91's three flags
(`TRUST_SAT=0`, `CLASSIFY_VERIFY_REFUTATIONS=1`, `SPIKE_CARD_ATOM=1`) all target the
*subsumption* path; the defect lived on the *satisfiability* probe, which had no escape
hatch for the construct. The absence of a working flag localised it.

**A control run on the wrong surface hid a second, worse defect.** #90's recorded control
read "`Self` OUTSIDE a `∀` is fine" — verified with `rustdl sat`, which passes. On
`classify`, `U ⊑ ∃r.Self` + `U ⊑ ¬∃r.Self` (two axioms, no `∀`) was **also** missed, with
Konclude reporting `EquivalentClasses(owl:Nothing, U)`; and unlike the subsumption cases
*no flag recovered it* — only disabling the wedge did. So the `∀` in the issue title was
incidental, and the issue has been retitled.

**Three reproducers of "one bug" did not share a mechanism.** Their clausifier deferral
counts were 2, 0 and 1 while all four fixtures printed an *identical* `# fragment:`
banner. `∀p.(¬Self ⊔ ¬Z)` had a complete clause set and still failed — which is what
proved the clausifier was never the whole story. Two distinct refusals were at work
(`NotTree` for the self-loop, `Disconnected` for a naming clause on an unbound successor
variable), and that is precisely why the previously-recorded anchoring patch "changed
nothing": on `X` the body becomes `R(X,X)`, which the *other* refusal then discarded. One
patch had been evaluated against three mechanisms.

## The corpus report's "+2 classified" is NOT a gain — it is contention

The 424-ontology gate reads **418 classified vs 416** against a host-matched v0.4.25
baseline, with **0 consistency-verdict flips and 0 lost**. The PASS is real; the +2 is
not, and it is recorded here because a favourable artifact is the more tempting kind to
accept.

Both legs ran at `JOBS=8`, and this repo already documents that parallel contention
manufactures cap-boundary flips. Re-measured sequentially on an idle host, 3 repeats per
arm with arm order alternated:

## The two-arm full sweep was deliberately SCOPED, not skipped

`RELEASE-PROCESS.md` lists a 1,920 × 2 sweep (~4 h/arm) to catch `ok → dnf`. It was not
run in that form for this release, and the reason is that there is no mechanism left for
it to find:

* **#98** was swept over its **complete addressable superset by construction** — the 497
  ontologies authoring any `(Object|Data)(Min|Max|Exact)Cardinality`, since only those
  three axioms build `Min`/`Max` and NNF preserves filler complexity rather than creating
  it. Result: 0 `ok → dnf`, 0 answer changes, wall −0.21%. Outside that frame the clause
  short-circuits on an empty set.
* **#90** is provably inert on ORE: its addressable set across all 1,920 is **0**, by two
  independent instruments. A change that cannot fire cannot cost an ontology its cap.

Anyone who disagrees with that scoping should run it; the argument is stated so it can be
checked rather than assumed. The 424-ontology report *was* run in full, host-matched, and
is the sweep-shaped evidence that exists.

## The corpus is INERT for all three fixes — read the gates accordingly

This is the honest framing and it matters more than the green ticks.

* #98 fires on **4** of the 497 cardinality-bearing ORE ontologies, and on all four the
  main tableau **confirms** the wedge's `Sat` — no new unsatisfiable class anywhere.
* #90's addressable set across all 1,920 is **0**, measured by two independent
  instruments: the engine probe (1,774 clean / 39 `VarCap`-only / 0 `NotTree`+`Disconnected`,
  its 107 unmeasured-at-30 s all retried at 300 s) and a new clausify-only probe that
  needs no reasoning and so *can* measure the ontologies that stall in it (1,918
  `FILTERS=0`, 2 unmeasured, both with `ObjectHasSelf`=0).

So the corpus gates here are **non-regression evidence only**. The evidence that the
fixes are *correct* is the canaries plus the Konclude/HermiT adjudications — the same
situation recorded for #70, #72, #78 and #81.

**`ro.ofn` is the exception, and the one place #90 is observable on real data:** 6
`NotTree` refusals → **none**, six clauses moving from silently-ignored to enforced, with
its oracle-verified closure **unchanged at 158=158**. That is what shows the fix is not
merely "more clashes".

## Direction of risk

All three fixes *add* constraints, so the failure mode is a false **positive**, not a
miss. Each therefore carries an oracle-adjudicated negative control rather than an
assumed one — for #90, a node whose `r`-successor is a *disjoint* class has no self-loop,
Konclude reports no unsatisfiable class, and rustdl agrees. A fix that ignored the
self-loop *condition* (firing on any `r`-successor) would break exactly that control, and
the pre-fix engine passed it only by ignoring the clause altogether.

## Also in this release

`examples/clause_stats_probe` — nothing surfaced the clausifier's `deferred` count, and
that probe is what split #90 into its two mechanisms. It also computes the match-plan
refusal census without running the engine.

`OrderReject::NotTree` is deleted (unconstructible once bound-target atoms become
filters). The unit test asserting `Err(NotTree)` for the legitimate join
`R(X,1) ∧ S(X,1)` **was pinning the defect** and is retargeted, joined by self-loop cases
on both the root and a successor.

The #93 agreement gate fired for the third consecutive day, and #90 was its **last** live
row — an empty roster would have passed vacuously. It no longer depends on a live defect:
it *manufactures* one by reverting a shipped fix through its own flag, and counts
comparisons made. Sabotage-validated.
