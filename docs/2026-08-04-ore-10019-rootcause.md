# `ore_ont_10019` — root cause: the sufficient-direction disjunction on a *shared* soft trigger, live in the MAIN TABLEAU only

**Status: root cause FOUND and localised. One fix was built, measured, REFUTED, and reverted.**
The tree is unchanged apart from this document (post-revert `target/release/rustdl` sha256
`2c7d1bbf0ed200fae176bc7a7c62fd74a1c6fad2feb0c5a37cad193b81846fdc`, byte-identical to the
pre-change baseline build).

Binary under test: v0.4.14 @ `e46e4ee`, built `RUSTUP_TOOLCHAIN=stable`, pinned to
`rustdl-v0414-base` (sha `2c7d1bbf…`) immediately after the build that produced it.

## 1. What the ontology actually says

A chemistry functional-group ontology (`dumontierlab`), 211 lines:

- **11 atom types** (`CarbonAtom`, `OxygenAtom`, `NitrogenAtom`, `SulfurAtom`, 5 halogens, …)
  made **pairwise disjoint** — that is the 55 `DisjointClasses`, a near-complete clique.
- **5 bond roles** (`hasBondWith` + `hasSingle/Double/Triple/AromaticBondWith`), **all
  `SymmetricObjectProperty`**, all with `domain = range = Atom`, the four specific ones
  `SubObjectPropertyOf hasBondWith`.
- **29 `EquivalentClasses`** defining functional groups, almost all of the shape
  `D ≡ CarbonAtom ⊓ =n bond.Filler ⊓ …` — e.g.
  `CarbonylGroup ≡ CarbonAtom ⊓ =1 hasDoubleBondWith.OxygenAtom`,
  `AcylHalideGroup ≡ CarbonAtom ⊓ =1 hDBW.OxygenAtom ⊓ =1 hSBW.HalogenAtom ⊓ =1 hSBW.OrganicGroup`.
- **4 covering unions**: `HalogenAtom ≡` 5-way, `HeteroAtom ≡` 4-way, `CarbonGroup ≡ Aryl ⊔ Alkyl`,
  and `Alkyl ≡ CarbonAtom ⊓ ∃hSBW.(HydrogenAtom ⊔ CarbonAtom)`.

### The stated structural profile was wrong in two places — verified by reading, not grepping

| | brief | actual (counted at all nesting depths) |
|---|---|---|
| `ObjectSomeValuesFrom` | 17 | **33** |
| cardinality | *"not cardinality … in any load-bearing form"* | **24** — 20 `ObjectExactCardinality` + 4 `ObjectMinCardinality` |
| tautological (`n = 0`) | — | **0**; the numbers are 1 (×15), 2 (×8), 3 (×1) |

Every `ObjectExactCardinality(n r C)` is `≥n r.C ⊓ ≤n r.C` (`convert.rs:956-961`), so there are
**20 at-most constraints**. Cardinality is not incidental here — **Konclude itself reports the
ontology as `SHIQ`**, and the `Q` is exactly this. `0 ∀` and `5 symmetric roles` were correct.

## 2. Ground truth

`Konclude` **0.04 s** and `HermiT` **2.31 s** (incl. ~0.56 s docker+JVM floor) agree **exactly**:
**162 pairs, zero disagreement in either direction.** A clean, uncontested oracle.

## 3. Baseline behaviour — and it is NOT a DNF

The brief's "DNF at 120 s" is not what happens on v0.4.14. `classify` **completes in 97 s** and
reports **159/162, FP=0**, with

```
⚠ INCOMPLETE: 154 class pair(s) hit the 1000 ms per-pair timeout
```

154 pairs × 1000 ms ≈ the whole wall. The 3 missed pairs are
`SulfinicAcidGeneralGroup ⊑ OrganicSulfurGroup`, `SulfoxideGroup ⊑ OrganicSulfurGroup`,
`SulfoxideGroup ⊑ SulfinicAcidGeneralGroup` — **not** `KetoneGroup ⊑ CarbonylGroup`, which is the
miss set of the *forced-depth-8* arm the brief quotes, not of the default.

**It is not a budget problem.** At a **15× budget** (`--pair-timeout-ms 15000`) the result is
**still 159/162, FP=0, and still exactly 154 incomplete pairs.** Those pairs are not slow; they are
undecidable by this search at any budget.

### The 3 missed pairs decompose cleanly — and only ONE is this root cause

| arm | pairs | FP | MISSED | wall |
|---|---|---|---|---|
| default | 159 | 0 | 3 | 97 s |
| `RUSTDL_LABEL_HEURISTIC=0` | 159 | 0 | **3 (same 3)** | — |
| **`RUSTDL_CLASSIFY_SAME_TIER=1`** | **161** | **0** | **1** | 139 s |

`RUSTDL_CLASSIFY_SAME_TIER=1` (default OFF, documented limitation: the tier walk groups by
EL/told-subsumer count and *never compares same-tier classes*) recovers
`SulfinicAcidGeneralGroup ⊑ OrganicSulfurGroup` and `SulfoxideGroup ⊑ OrganicSulfurGroup`. So **2 of
the 3 are an orthogonal, already-flagged tier-walk gap, not this root cause.** The label heuristic
is *not* implicated (turning it off changes nothing) — a hypothesis this investigation raised and
refuted.

The **one** genuinely blocked pair is `SulfoxideGroup ⊑ SulfinicAcidGeneralGroup`, and it is blocked
by the §5 mechanism: `rustdl explain` on it does not return (>3 min), whereas `explain` on the other
two *does* prove them ("answered by tableau"). **So 162 is reachable on this ontology only by fixing
§5 — and 161 is reachable today with one existing opt-in flag.**

## 4. The branching source, with counts

### 4a. In the wedge, one class is 99.6% of all work

`hyper-sat` (per-class wedge satisfiability), 47 classes:

```
# stalled: 2      # total_branches: 375318      # total_wall_ms: 5010.6
Stalled wall=5001.64ms branches=373919 restores=373919 depth=256   KetoneGroup
Stalled wall=6.36ms    branches=1278   restores=1278   depth=256   AcylGroup
Sat     wall=0.34ms    branches=12                     depth=7     AldehydeGroup
…every other class ≤ 12 branches
```

`KetoneGroup` alone is **373,919 / 375,318 branches (99.6%)** and **5001 / 5011 ms (99.8%)**.
`restores == branches` — every branch fails.

### 4b. In the main tableau, 36 of 47 classes never terminate — including bare atoms

`rustdl sat <class>`, 5 s cap, one process per class: **36 hang, 11 complete.** The 36 include
**`CarbonAtom`, `NitrogenAtom`, `OxygenAtom`** — *primitive atoms with no definition, no `∃`, no
cardinality of their own*. Proving a bare atom satisfiable should take zero search.

**The 11 that complete are exactly the atoms that are not a soft trigger of any defined class:**
`AstatineAtom`, `BromineAtom`, `ChlorineAtom`, `FluorineAtom`, `IodineAtom`, `HydrogenAtom`,
`PhosphorusAtom`, `SulfurAtom`, plus `Atom`, `HalogenAtom`, `HeteroAtom`. Everything reachable to
`CarbonAtom` / `NitrogenAtom` / `OxygenAtom` / `OrganicGroup` / `CarbonGroup` hangs; nothing else
does. **That partition is the single sharpest piece of evidence in this investigation** — the
failure set is predicted exactly by "does a shared soft trigger appear".

### 4c. The model is bounded; the search TREE explodes

`RUSTDL_TRACE=1` on `sat KetoneGroup`, 103,494 trace lines:

- `graph_nodes` rises to ~210 and then **oscillates 207–243** — a bounded model, not runaway
  generation. `RUSTDL_MAX_NODES` is never approached.
- Branch decisions concentrate on **one node: node 9 gets 17,860 of 20,002** (node 10: 1,407,
  node 11: 402).
- Depth oscillates inside a window of **18** (999874–999892) at branch #11,630.
- Every clash is `clash=immediate`, and its dep-set is **`deps = 110–112`** — the clash is recorded
  as depending on ~111 ancestor branch decisions, so **dependency-directed back-jumping can prune
  almost nothing** and the same refutation is re-derived thousands of times.
- Option widths seen on node 9: `options=2` (11,839), `5` (5,017), `7` (602), `3` (402). The 5-way
  is the `HalogenAtom` covering.

### 4d. `concept_rule_or = 29` — one disjunctive concept rule per defined class

`tbox-stats`: `concept_rules: 182`, **`concept_rule_or: 29`**, `residual_gcis: 5`.
`residual-absorbability`: all 5 residuals are `domain_absorbable`, `zero_residuals_under_domain:
true`, and `conclusion_is_or: 29` with **`..with extra ¬Atomic: 0`** — so none of the 29 is a
binary-absorption candidate. The 29 `Or`-concluded concept rules are one per `EquivalentClasses`.

## 5. Root cause

The **sufficient (⇐) direction** of a defined class `D ≡ soft ⊓ hard₁ ⊓ … ⊓ hardₖ` is absorbed by
negating the *hard* conjuncts into a **disjunctive head anchored on the `soft` conjunct**:

```rust
// crates/owl-dl-core/src/clause.rs:471-477
// Head = (¬hard_1 ⊔ … ⊔ ¬hard_k) ⊔ sup.
let mut head_parts: Vec<ConceptId> =
    hard.iter().map(|&h| crate::normalize::nnf_complement(h, &mut self.pool)).collect();
head_parts.push(sup);
let head = self.pool.or(head_parts);
```

with the trigger chosen as the **first** `Not(Atomic)` disjunct (`absorb.rs:461-468`, `break` on
first match). There is **no surrogate / definitorial atom**: the hard conjuncts become a negated
head, which is *don't-know nondeterminism where HermiT and Konclude have none*.

Three facts then compose into the stall:

1. **The soft trigger is SHARED.** ~15 of the 29 defined classes have `CarbonAtom` as their soft
   conjunct. So **every node labelled `CarbonAtom` acquires ~15 open disjunctions at once**, purely
   from being a carbon atom.

2. **The open-test is purely syntactic, so those disjunctions never close.**
   ```rust
   // crates/owl-dl-tableau/src/search.rs:502-503
   if let ConceptExpr::Or(args) = pool.get(c)
       && !args.iter().any(|d| labels.binary_search(d).is_ok())
   ```
   A disjunction is "open" iff **no disjunct is syntactically in the label set**. The
   cardinality-complement disjuncts — `¬(=1 r.C)` NNFs to `≤0 r.C ⊔ ≥2 r.C`, and `ConceptPool::or`
   flattens that into the head — are *semantically true on almost every node* (a node with no
   `r`-successor trivially satisfies `≤0 r.C`) but are **never syntactically present**. So the ⊔
   rule branches on all ~15, on every trigger-carrying node, forever.

3. **Choosing the `D` disjunct regenerates the trigger.** Picking `D` imposes `D`'s own
   `∃`/`≥n` conjuncts, which generate fresh `CarbonAtom`/`OrganicGroup` nodes (`Alkyl`'s
   `∃hSBW.(H ⊔ C)` supplies an unbounded stream), and each fresh node re-opens the same ~15
   disjunctions. The 55 pairwise-disjointness axioms make most combinations clash immediately —
   which is why the model stays bounded while the tree does not.

### Minimal reproducer: TWO sufficient directions

Delta-debugging over which of the 29 `EquivalentClasses` keep their ⇐ direction (turning the rest
into `SubClassOf`, i.e. dropping only the ⇐ half):

| kept as `≡` | `sat KetoneGroup` |
|---|---|
| all 29 | hangs (>30 s) |
| **`{AcylHalideGroup, Alkyl}`** | **hangs** |
| `{AcylHalideGroup}` only | **sat, 11 ms** |
| `{Alkyl}` only | **sat, 10 ms** |
| none (all 29 → `SubClassOf`) | **sat, 10 ms** |

**No single class is responsible** (all 29 one-at-a-time ablations still hang). The minimal pair is
`Alkyl` — the *generator*, `CarbonAtom ⊓ ∃hSBW.(H ⊔ C)`, which manufactures fresh `CarbonAtom`
nodes — plus `AcylHalideGroup`, whose ⇐ direction fires a fresh 4-disjunct head on each of them and
whose `AcylHalideGroup` disjunct re-opens the 5-way `HalogenAtom` covering. With only these two the
graph grows to **1,563 nodes** (generation-bound); with all 29 it stays at ~210 (branch-bound).

### Why the wedge and the main tableau differ

`clause.rs:143-156` documents a fix for **exactly this ontology, by name**:

> `RUSTDL_CARD_DISJUNCT_ATOMS` (**default ON**) … An opaque `Q` is never recognized as
> already-satisfied (`head_atom_satisfied` checks `node.has(Q)`), so a `¬cardinality` disjunct in a
> defined class's sufficient-direction clause keeps the clause perpetually "open" and the search
> branches spuriously — the dense-SROIQ over-branching (**`ore_ont_10019`: bare `CarbonAtom` stalls
> at 7000 branches**).

Measured, ON vs OFF:

| | wedge (`hyper-sat`, all classes) | main tableau (`sat KetoneGroup`, 20 s cap) |
|---|---|---|
| `=1` (default) | 5.0 s / 377,516 branches | hangs, 25,632 branch lines |
| `=0` | **exceeds 60 s** | hangs, **25,608** branch lines |

**The flag transforms the wedge and does nothing whatever to the main tableau.** The fix was
delivered to `hyper.rs::head_atom_satisfied` only; `search.rs`'s ⊔ open-test never received the
analogue. Profiling attributes **84.6% of the stall to the main tableau** vs 15.3% `hyper::solve`.

## 6. Does the recorded over-branching hypothesis hold?

**Yes — as a diagnosis it is correct, and it is still live. But it is a *partial* cause, and its
prescribed fix does not work.** Specifically:

- ✅ The mechanism is right: a defined class's sufficient direction clausified as a disjunction
  anchored on a shared conjunct, in `absorb_hard_antecedent`.
- ✅ The named symptom **still reproduces**: bare `CarbonAtom` still stalls — in the **main
  tableau**. It no longer stalls in the *wedge*, which is where the 2026-07-16 probe measured it;
  `RUSTDL_CARD_DISJUNCT_ATOMS` closed that half. Anyone re-running the old `hyper-sat` probe today
  will see `CarbonAtom` come back clean and wrongly conclude the hypothesis is dead.
- ❌ **"The over-branching is pure waste" (the 2026-07-16 spike) does not survive.** That spike
  *deleted* the ⇐ clauses — changing the axiom set, and losing 12 real subsumptions. Suppressing
  their *firing when already satisfied* instead (§7) shows the branching is **load-bearing: it is
  what currently contains generation.** Remove it and the graph grows instead.
- ❌ Surrogate-atom absorption is therefore **not** simply "the fix"; see §8.

## 7. The fix I built, and why it is REFUTED (reverted)

Ported the wedge's satisfaction check to the main tableau: gate `RUSTDL_OR_CARD_SATISFIED`
(default OFF), a `max_disjunct_satisfied` predicate added as an extra reason to consider a
disjunction closed — a `Max(n, R, C)` disjunct counts as satisfied when the node has ≤ n distinct
`R`-neighbours labelled `C`, counted with the **same** `neighbours()` + `edge_satisfies` +
`has_label` idiom `rules::apply_max` uses (so role hierarchy and the five **symmetric** roles are
honoured on already-correct code). `Min` deliberately excluded: distinctness is approximated by
distinct `NodeId`, which over-counts, and over-counting is conservative for `Max` (errs toward
branching) but *unsafe* for `Min` (would err toward suppressing a needed branch).

**Instrument fired** — criterion declared in advance (branch count in a fixed 5 s window must
differ ON vs OFF), and it did, from trace line 2. It did precisely what it was designed to do:

| `sat CarbonAtom`, 5 s | OFF | ON |
|---|---|---|
| branch lines | 12,202 | **6,183** |
| `options=7` decisions | 143 | **0** |
| `options=5` decisions | 1,175 | **6** |
| max `graph_nodes` | 135 | **257** |

**But it did not make one single class decidable.** The cardinality-complement branching is
eliminated, and the search converts from *branch-bound* to *generation-bound*: nodes 135→257 on
`CarbonAtom`, 243→657 on `KetoneGroup`, with decisions spreading from 11 nodes to 133. The residual
`options=2` decisions (~3,200, unchanged) are `Alkyl`'s `H ⊔ C` and `CarbonGroup`'s `Aryl ⊔ Alkyl`
— genuine covering disjunctions, not cardinality complements.

Because the flag makes the target *worse* when enabled and fixes nothing, **the code was reverted
rather than shipped as dormant scaffolding** — a default-OFF flag that only ever hurts is a trap.
The rebuilt binary's sha256 matches the pre-change baseline exactly. The patch is ~40 lines and is
fully specified above if anyone wants to reproduce the measurement.

### Also refuted, each by direct measurement

| intervention | result |
|---|---|
| `KetoneGroup`'s `=2` → `≥2` (drop the `≤2` half only) | still hangs |
| `KetoneGroup`'s own `≡` → `⊑` (drop **its** ⇐ direction) | still hangs |
| drop `SymmetricObjectProperty(hasSingleBondWith)` | still hangs |
| `RUSTDL_ANYWHERE_BLOCKING=1` / `=0` / `RUSTDL_HYPER_DOUBLE_BLOCK=0` | all still hang |
| `Alkyl` filler → `HydrogenAtom` only (no disjunction) | still hangs |
| `Alkyl` filler → `CarbonAtom` only (no disjunction) | still hangs |

The last two matter: the obvious "pick the non-generating disjunct `H` and terminate" story is
**wrong** — removing `Alkyl`'s disjunction entirely, in either direction, does not help. The
generator is the 29 ⇐ directions collectively, not that one union.

## 8. What Konclude does differently

**It is not searching at all.** 20 ms of classification for 47 classes, self-reported as `SHIQ`.
Per the code's own comment (§5) and the 2026-07-16 Phase-0 analysis, HermiT and Konclude apply a
**structural / definitorial transformation**: each hard conjunct becomes a **body surrogate atom**
`Mᵢ ≡ hardᵢ`, so the sufficient direction is the **Horn** rule `soft ⊓ M₁ ⊓ … ⊓ Mₖ → D`. That rule
fires only when the markers have genuinely been derived on the node — **zero disjuncts, zero
don't-know nondeterminism**, and, crucially, it *never speculatively asserts `D`* and so never
speculatively generates `D`'s successors. rustdl instead flips the hard conjuncts into a negated
disjunctive head, which both branches *and* speculates.

So the correct target is not "recognise a satisfied cardinality disjunct" (§7 shows that is
necessary but not sufficient) — it is to make the ⇐ direction **deterministic**, which removes the
branching and the speculative generation *in one move*. The delicate sub-problem, as the Phase-0
doc already identified, is the **reverse derivation of a cardinality surrogate**: deriving `Mᵢ` on
a node that genuinely satisfies `≤n r.C` is itself a hard-antecedent problem. That is standard DL
absorption territory and is unbuilt here.

## 9. Recommendation

1. **Do not re-run the old `hyper-sat` bare-`CarbonAtom` probe as the test of this hypothesis.**
   It now reads clean because the wedge was fixed, while the defect is live in the main tableau.
   The correct probe is `rustdl sat <class>` over all 47 classes: **36 hang, and the 11 that do not
   are exactly the non-trigger atoms.**
2. **Retract "the over-branching is pure waste."** Measured here: the branching is what bounds the
   completion graph. Any fix that only suppresses branching will convert this into a generation
   blow-up, as §7 did.
3. **The only fix shape consistent with all the evidence is Horn/definitorial absorption of the
   sufficient direction** (surrogate body atoms), because it is the only one that removes the
   branching *and* the speculative generation together. Price it as a `owl-dl-core` preprocessing
   change with a genuine open sub-problem (cardinality-surrogate reverse derivation), not as a
   tuning knob. It is semantics-preserving in principle (a fresh name defined by an equivalence
   adds no entailments over the original signature), so it should be verdict-preserving and FP-safe
   *by construction* — but that must be verified, not asserted, and the ~15-ontology superset check
   plus the MISSED net (baseline 5,198) are the gates.
4. **Only 1 of the 3 missed pairs belongs to this root cause** (§3). Two are the documented
   same-tier tier-walk gap and are recovered *today* by `RUSTDL_CLASSIFY_SAME_TIER=1` → **161/162,
   FP=0, 139 s**. Do not fold them into the absorption work, and do not attribute them to the label
   heuristic — that was tested and refuted. The remaining
   `SulfoxideGroup ⊑ SulfinicAcidGeneralGroup` needs §5. **No default should be flipped on this
   evidence**: `CLASSIFY_SAME_TIER` is default OFF for measured reasons (corpus-invisible, ~2× wall),
   and one ontology is not a population — the 139 s here is itself a +43% wall on this file.

## 10. Method notes

- **The stated structural profile was wrong twice** (§1), in the direction that would have steered
  the investigation away from cardinality. `grep -c` on a top-level pattern under-counts nested
  operands; `grep -o | wc -l` at all depths, plus reading the 29 definitions, is what corrected it.
  Konclude's own `SHIQ` verdict was the cheapest independent confirmation.
- **"DNF at 120 s" was itself a mis-description** — it completes in 97 s with a documented
  `INCOMPLETE: 154`. Reading the stderr banner rather than the exit status changed the whole framing
  from "hang" to "154 pairs × the per-pair budget".
- **My own harness had a bug that produced a confident wrong reading.** Extracting class IRIs with
  `grep -oE 'Declaration\(Class\(<[^>]+>' | sed 's/.*<//'` leaves a trailing `>`, so 47 probes were
  malformed IRIs that failed instantly. That is what produced an early "all KetoneGroup pairs decide
  in 306 ms total" — a *retracted* measurement. It surfaced only because a later scan reported
  `hang=0 ok=47`, which contradicted a directly observed 30 s hang. **A result that contradicts an
  earlier direct observation is a harness bug until proven otherwise.**
- **A single instance beat every population statistic again.** The decisive artefacts were the
  36/11 partition and the 2-axiom minimal set, both obtained by ablating one 211-line file.
- **Reverting a refuted fix is part of the result.** The byte-identical sha after revert is the
  evidence that the tree carries no speculative change.
