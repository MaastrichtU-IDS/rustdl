## 2. The DNF tail: 14 → 12, and the taxonomy was wrong

**Do not trust the "Bucket A / Bucket B" split.** It is falsified — see
`docs/2026-07-30-dnf-tail-is-one-bucket-not-two.md`. It was an artefact of *which budget each phase
honours*, not two mechanisms: `--pair-timeout-ms` does not bound the label-cache build (Phase 8
decoupled them deliberately), so "still DNF at pair=5 ms" never meant "cost is outside the per-pair
loop". `ore_ont_7499` completes in 28.73 s at pair=5 ms — it was never Bucket B.

Current tail (12): `5964 6485 8273 8666 13545 5438 5548 7499 7712 10080 4410 5368`.
All one mechanism: **per-class / per-pair wedge satisfiability on dense disjunctive SROIQ.**

### Three hypotheses eliminated BY MEASUREMENT — do not re-run these

1. **Axiom volume.** The collapse/broadcast split removed 54% of `5548`'s disjointness axioms and
   halved its RSS (541,575 → 250,546; 949 MB → 506 MB). Still DNF.
2. **Deadline not enforced inside `horn_fixpoint`.** Structurally true (`solve` checks the clock once
   on entry, then runs up to `FIXPOINT_ITERS = 100_000` events uninterrupted) but adding a sampled
   in-loop check changed **nothing**, like-for-like. In incremental mode each drain is a small delta,
   and `solve` already checks per entry.
3. **The per-class clause clone** (`HyperCache::classify_labels`, `self.clauses.clone()`).
   Measured 0.55–6.3% of CPU. Real waste, and still the unfixed sibling of v0.3.39 — but not a DNF
   lever.

### What IS confirmed, and where to aim next

A **~10–27× per-class budget overrun**: ~413/549/457/198 CPU-ms per class on
`5548`/`10080`/`7712`/`5438` against a 20 ms deadline. Only ~6% is the clone, so ~94% is per-class
`HyperEngine` construction, seeding and solve — pre-deadline or not deadline-checked.

**Assume the cost is DISTRIBUTED. Stop hunting hotspots** — three are now dead. Target either the
*number* of per-class wedge calls or their shared structure. The untried idea is sharing
class-independent work across per-class calls (`RUSTDL_HYPER_INCREMENTAL_FIXPOINT` already does this
*within* one solve; across classes is untried, and is the parked build-once-classify-many idea).
Measure the shared-prefix fraction before building: a single `10080` subsumption already costs >1 s,
so sharing only wins if the shared portion dominates one call.

## 4. Measurement failures — the highest-value part of this handoff

**Five retractions this session. Every one a sampling or instrumentation error; none a code error.**
The shipped code was right each time; my measurements of it were repeatedly wrong. If you take one
thing from this document, take this section.

1. **"3 ontologies benefit"** — selected on *residual ≥1M concept_rules*, a threshold, not the binding
   predicate. True figure **286**; 282 of them lie below that line. This nearly killed a lever that
   went on to recover 2 DNFs.
2. **"28.1% of corpus pairs droppable"** — a 30 s per-item timeout excluded the 17 largest ontologies,
   and the two largest turned out to be almost entirely non-droppable (`2504`: 98 of 68.7M). A
   per-item timeout is **not a neutral sampler** — it selects against the largest items. True figure
   **9.53%**.
3. **A sabotaged binary measured as if it were the change.** To prove canaries non-vacuous I forced a
   gate to skip everything, rebuilt, observed the expected failures, reverted the *source* — and never
   rebuilt. A later `cp target/release/rustdl` captured the sabotage build; a 2-hour scan measured it.
   `9347` reads 113 under **both** the real gate and a zero-pairs build, so the sanity check could not
   discriminate. `5368` was the discriminator.
4. **The deadline hypothesis**, prototyped and reported before its own test refuted it.
5. **Two claims from an instrument that was not in the binary.** I pattern-matched one of **nine**
   `clauses.clone()` sites and landed in an unused function; the compiler removed the diagnostic and
   every run printed nothing. I read that silence as data for three rounds
   ("fewer than 250 classes in 60 s", "~400× overrun"). Both false — 3,500–9,700 classes per 60 s.

### Rules earned the hard way

- **Pin a binary to a uniquely named path immediately after the build that produced it**, name the
  path after the configuration, and **verify the pin against an input that discriminates the
  configurations** before trusting a scan built on it. For DKey work: `9347` cannot discriminate
  (zero ranges) — use `5368` (must read 18,620,251) and `7607`.
- **Confirm a diagnostic is in the built binary** (`strings <bin> | grep <marker>`) before
  interpreting any measurement. *Silence from an absent instrument is indistinguishable from silence
  from a slow program.*
- **Anchor a source edit on text unique to the target function** and assert the match count. Nine
  sites shared the pattern I used.
- **State the timeout AND the exclusions** with any population claim.
- **Sabotage your own guard tests** — break the guarded code and confirm the test fails. A
  differential test added this session passed under three separate sabotages of the thing it was
  written to guard; it was documented as *not* closing that finding rather than overclaimed.
- Change **one** variable per comparison. One "verification" run silently dropped
  `RUSTDL_LABEL_CACHE_TIMEOUT_MS` and was uninterpretable, not negative.
- `tail` in a pipeline buffers to EOF — an outer timeout kills the loop and you lose everything.
  Write per-item output to files.
- The `# wall breakdown ms:` banner only prints on a **completed** classify, so it is useless on a
  DNF. Use `RUSTDL_TRACE_RSS` phase probes; the last marker emitted localises the stall.
